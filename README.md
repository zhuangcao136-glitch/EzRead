# EzRead

Windows 个人论文库。按论文插图浏览文献，接着上次位置进行英中对照精读。

## 打开

双击桌面的 **EzRead** 快捷方式，或本目录的 **`启动EzRead.vbs`**。

项目根目录为本 README 所在目录，默认文献库为该目录的 `data/`。在 Windows 上可运行本目录的 `setup-desktop.ps1` 创建或重建当前用户的桌面快捷方式；移动程序后重新执行该脚本。

应用在 EzRead 自己的 Windows 窗口中运行，内嵌 WebView2，启动器不再打开 Edge/Chrome 应用模式窗口。后台仅监听本机 `127.0.0.1:47831`。关闭窗口前等待笔记与阅读位置保存，网络失败时保留本机草稿；关闭窗口不结束后台任务。再次启动会恢复已保存内容，重复启动会回到已有窗口。

标题栏不显示文字或书本小图标；任务栏与 Alt+Tab 的书本图标由 EzRead 的桌面 EXE 自己持有，不依赖网页 favicon 或外部图标维护进程。

项目目录为本 README 所在的文件夹。启动器核对服务的程序目录和文献库目录；若端口由旧版本或另一处文献库占用，会明确提示，不会自动结束其他进程。后台日志位于实际文献库的 `server.log`。

源码版需要 Python 3.10+、`requirements.txt` 中的包、.NET Framework 4.8 和 WebView2 Runtime；模型功能另需已登录的 Codex CLI。首次运行源码版，执行 `powershell -File scripts/build-desktop.ps1` 构建桌面组件（x64）。脚本从微软 NuGet 获取固定版本 SDK 并核对 SHA-256，不打包完整浏览器内核，也不需要安装 Visual Studio。随后可运行 `python launch.pyw` 或 `python server.py --open`；桌面 VBS 启动器沿用本机已检测到的 Python。移动程序时保留完整文件夹，并重新设置快捷方式。目前已具备原生桌面窗口，尚未制作包含 Python 的通用安装包。

WebView2 运行时缺失时明确提示，不退回外部浏览器窗口。运行时可从[微软官网](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)安装。普通开发仍可只运行 `python server.py`，手动通过浏览器访问本机地址。

WebView2 状态保存在实际文献库的 `webview2-profile/`，窗口位置保存在 `desktop-window.json`，启动诊断保存在 `desktop.log`。首次切换会只读提取原 `browser-profile/` 中属于 EzRead 本机地址的排序、偏好和草稿，写入 `webview2-migration.json`；不读取其他网站、账号或 cookies，不覆盖新窗口已有值，也不删除旧 profile。论文、译文和已保存笔记继续使用同一 SQLite 库。

## 导入与精读

右侧文章保留标题、自然段和公式排版，正文可以直接拖选、按 Ctrl+C 复制。选中文字后右击，可复制、高亮、添加批注、修订原文或译文、翻译单词、翻译句子，以及定位原 PDF。跨段高亮与批注保存为一条标记；点击文字标记或批注图标打开查看／编辑卡片。旧段落高亮和批注继续保留，不被猜测转换为句子范围。

“英文原文／译文”切换右侧显示内容，便于翻译后继续校订英文。修订仅替换所选文字，原 PDF 与最初提取的原文保持原样；“修订历史”可恢复修改前的文字。修改英文不会自动重译，已有译文保留并提示待核对；“重新翻译对应段落”由用户主动触发。文字改变后，标记仅在原句能唯一可靠定位时跟随；找不到时保留批注与引用，显示“待核对标记”。

选区不自动调用模型；右键“翻译单词”查离线词典，“翻译句子”才调用模型。编辑期间的本机草稿保留，后台轮询不替换当前选区或打开菜单的正文节点。

1. 拖入一个或多个 PDF。原件复制到文献库，重复导入不会重复建档；新论文显示在“全部论文”，合集由你手动选择。后台继续整理原文结构，不自动归入或创建合集；已有论文的合集归属保留。导入后由你决定何时开始翻译。
2. 点击图片卡片直接阅读或续读；独立的“论文简介”入口用于查看资料。导入时提取论文插图，选中图片后可直接设为封面，或在该图片内框选裁剪。
3. 全文翻译采用串行队列，支持批量加入、暂停、重试和断点续译。电脑重启后可手动继续未完成任务。
4. 对照阅读左侧连续滚动原版页面，右侧为译文；未翻译时右侧直接显示英文正文。双栏宽度可调，笔记按需展开。可切换滚动同步；点击段落可定位原文。PDF 缩放独立于中文字号，并保存续读状态。
5. 批注、笔记、译文修改与阅读位置持久保存，编辑过程中保留草稿。研究速览、作者和团队背景可以按需生成或更新。

## 外观与字号

设置中可选择纸白、暖米、浅绿、石墨主题，分别调整界面与中文阅读的字号。文字统一使用系统字体。默认界面 16px、中文正文 18px，修改即时预览并保存，支持恢复默认。

“设置 → 期刊等级”可以查看、搜索和编辑期刊名单，各等级内按刊名 A–Z 排序，右侧字母可快速定位。标题右侧提供搜索框，页面固定在窗口内，列表填满剩余空间并单独滚动，保持正常字号和行距。搜索不区分大小写，按匹配程度排序，输入时在搜索框下展示候选期刊及彩色评级；支持鼠标、上下键和 Enter 选择。支持手动编辑与移除；编程助手可通过独立模块、HTTP 接口或 `scripts/journal-catalogue.py` 新增或修改名单，使用同一校验与保存流程。保存后自动刷新已导入论文的等级、颜色与筛选，无需重新导入。初始名单保留在源码中，个人名单及历史备份保存到当前文献库，详见 [名单与编辑接口](JOURNAL_TIERS.md)。

卡片按固定期刊等级呈现覆盖整张卡片的纯色半透明质感：顶级为金色、重要为柔和蓝色、其他期刊为森林绿；会议为暖灰色毛玻璃，预印本为白色。多选圆框位于卡片右上角，替换删除图标；未选中为白色圆框，选中时改为黑色底与加粗白色对勾，不随卡片等级或主题变化。卡片点击直接阅读，详情仍有独立入口。

卡片、按钮、输入框、菜单和弹窗采用统一的连续圆角规则，按组件大小调整半径；封面各层使用一致的轮廓。卡片外沿为淡白柔光，顶部稍亮、底部更淡，不再显示内缩的白色框。石墨主题适当降低高光亮度。现代 Edge/Chrome 使用连续曲线，不支持的浏览器回退为常规圆角；样式集中在最后加载的 `static/surfaces.css`。

文献库随窗口宽度自动调整列数，等宽卡片填满主区，按内容确定高度并依最短列紧凑排列。底栏也随窗口伸缩，缩小窗口无需横向滚动。论文标题统一使用英文原题，字号较紧凑；封面右侧依次显示全文翻译、论文简介、模型及推理强度、对话四个按钮，与封面区域上下对齐。封面完整显示并保持比例，长图自动缩放；按钮间距固定，四个按钮随封面高度等分伸缩。未译完时按钮显示“全文翻译”，已译完时显示“已翻译”；点击后须在确认窗口再次确认才会开始翻译或整篇重译，取消不会加入队列。期刊来源在卡片和论文简介中显示简称，悬停可查看完整刊名；未核实正式简称的期刊使用仅供界面显示的缩写。卡片用颜色表示期刊等级，不显示简介摘要；阅读位置继续保存，不再判定已读。

侧栏常驻，按“筛选—排序—主要合集”组织。再次点击当前选中的“我的收藏”或主题合集，会退出该视图，保留其他筛选和排序。期刊论文可继续按出版来源、期刊等级筛选；排序提供“最新导入／最早导入、最新发表／最早发表、最近读过／最久未读”六个文字选项，当前仅一项高亮；可与筛选和合集组合使用，刷新后保留选择。缺少年份或阅读记录的论文放在末尾。

右键论文卡片提供“多选、复制 PDF、在文件夹显示”。点击“多选”会自动选中当前卡片，随后可以点击其他卡片混选；主区顶部左侧为“取消”，右侧依次为已选篇数、全选、清空选择、移入合集、全部翻译、移入回收站。“全选”针对当前筛选结果；点击取消或按 Esc 退出并清空选择，弹窗内的 Esc 优先关闭弹窗。批量翻译仍需在确认窗口明确开始。普通模式保留收藏和删除按钮，多选模式保留收藏并将删除位置替换为勾选圆框，退出后恢复删除按钮。

“复制 PDF”复制文件本身到 Windows 剪贴板，随后可 Ctrl+V 粘贴到文件夹或支持文件粘贴的聊天窗口。复制使用 [Windows FileDrop 剪贴板接口](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.clipboard.setfiledroplist)，保留导入时的文件名；库内原件不改名，待粘贴文件缓存在 `data/clipboard/<论文 ID>/` 并供后续复制复用。“在文件夹显示”会打开原件所在目录并选中 PDF。

主要合集下显示“可将论文卡片拖入合集”。拖动时鼠标旁出现缩小的封面、标题与篇数预览，原卡片保持清晰，目标合集高亮；拖动已选卡片会移动全部已选论文，拖动未选卡片只移动这一篇。侧栏不再显示多选和垃圾桶入口，“偏好设置”改为“设置”；删除进入回收站，可在“设置 → 文献与备份 → 查看回收站”中恢复。

## 翻译模型与推理强度

侧栏的“翻译任务”打开弹窗，背景模糊，列表在框内上下滚动；顶部保留刷新和关闭按钮。关闭或按 Esc 后回到原来的文献库筛选与浏览位置；Ctrl+K 可关闭弹窗并聚焦搜索。

在设置中选择全局默认模型与推理强度；卡片可为每篇论文固定模型。首次问答、研究速览或全文翻译时解析默认值并锁定到该论文。可选项由官方 Codex 的 `model/list` 动态提供，推理强度随模型变化；“官方默认”在首次任务前解析为目录明确给出的具体值。

每个全文翻译任务保存当时的模型和强度，修改全局默认或本篇模型不改变正在运行的任务。同一配置可断点续译；更换本篇模型后，若要新模型的译文，需手动发起整篇重译。重译结果先暂存，完成前保留当前译文，历史版本和编辑草稿可恢复。团队背景联网查询继续使用独立流程。

模型目录在后台刷新，不阻塞本地阅读。刷新失败会区分旧目录与不可用；目录尚不可用或组合不受支持时会说明原因，不虚构模型选项。更高推理强度的耗时与额度使用可能不同，不等于译文必然更准确，仍需保留原文核对。

## 论文对话与划线翻译

右侧文字按论文结构连续阅读：标题、作者、单位、Article Info、Abstract，再按正文节/小节和自然段排列，不按 PDF 页码分组。点击段落仍可定位左侧原 PDF，已有译文、批注和手工修订保留原编号。

导入新论文时自动加载 `skills/ezread-paper-import/` 中的处理流程：先在本机生成可读结构，再用设置中的快速模型后台校对首页信息与标题候选，并共用一次调用判断研究主题合集。校对使用 Codex 订阅额度，发送候选文字及上下文、标题摘要和已有合集示例；模型只分类源块与主题，不改写英文全文。结果保存后重复打开直接复用。失败保留本地结构，并提供“重试整理”。已有文献自动使用本地结构，必要时手动点击“校对结构”。扫描件仍需要 OCR；旧导入丢失的数学字符不能由结构整理补造。

卡片或阅读器上栏的“论文对话”进入该论文独立的问答历史；默认只依据导入的论文、已保存译文和笔记回答，并给出可跳转的原文页码与段落。首次问答才创建持久 Codex 会话；每篇论文的全文翻译另用独立会话。对话可在 EzRead 中继续，也可通过对话侧栏入口在 Codex 桌面端打开。模型切换会新建上下文并注入结构化交接资料，旧对话可在版本选单中回看。

在右侧正文中选择单词、词组或句子，在自动显示的选区菜单中选择“翻译单词”或“翻译句子”。左键划选本身不调用模型，普通选区与 Ctrl+C 保持原生行为。

“翻译单词”查询内置 ECDICT 离线英汉词典，提供音标、释义和词形匹配；不要求 Codex 登录，不使用模型额度，未收录时明确提示并保留手动选择句子翻译的入口。词库约 58 MB，来源、固定版本、字段和校验值见 `assets/dictionaries/source.json`，MIT 授权文本随词库保留。需要重建时，先从该记录的固定来源下载 CSV，再运行 `python scripts/build-dictionary.py <本地 CSV 路径>`；不会在打开阅读器时下载词库。

“翻译句子”使用设置中保存的划线模型与推理强度，默认模型为 `gpt-6-luna`；目录不可用时不会暗中换用其他模型。专用 Codex 进程按需启动并复用，每次选区创建独立临时会话，禁用无关工具、插件、记忆和技能。完整、有效的最终译文到达即显示，不等待进程退出或账户通知收尾。换选区、关闭翻译卡片或阅读器会取消旧请求并中断模型轮次；旧响应不能覆盖新卡片，翻译期间正文变化也会拒绝过期结果。译文仅临时显示，不写入批注、论文问答或全文译文。

## 期刊、会议和预印本

- **期刊**：卡片只显示顶级、重要或其他，依据 [2025 年固定名单](JOURNAL_TIERS.md)；纳入学院明确目录，并按学院 2023 年细则采用最后一版 2025 年中科院分区。同时命中“重要”和 2025 年顶级条件时归顶级。导入时只匹配固定名单，不再获取或显示影响因子及分区。
- **会议**：统一暖灰色毛玻璃卡片，不显示会议评级。
- **预印本 / 未发表**：统一白色卡片，不赋予期刊或会议等级。发现 arXiv 链接不代表论文仍未发表；确认正式版本后应校正文献类型与出版来源。
- 等级仅表示期刊类别，不代表单篇论文质量或毕业资格。固定名单未命中的期刊显示“其他”；信息不确定时可通过论文简介中的名单依据核对。旧数据库中已有的指标字段暂不删除，以免损坏历史文献，但接口和界面不再提供这些数据。

## ChatGPT 订阅与额度

翻译使用官方 Codex CLI 的 ChatGPT 登录，不使用独立付费翻译 API，也不读取或复制账号令牌。若未登录，在终端运行 `codex login`，使用 ChatGPT 账号完成登录。

额度通过官方 Codex app-server 的 `account/rateLimits/read` 读取，显示接口实际返回的使用比例、剩余比例、重置时间和更新时间，支持手动刷新。

这是 **账号共享的 Codex 额度**，包括其他 Codex 会话的使用，不代表所有 ChatGPT 功能的总额度，也不能归因到某一篇论文。接口未返回的时间窗口不会显示为 0；刷新失败会标明旧数据或暂不可用。读取额度本身不发起模型请求。

额度耗尽时保留已完成译文，恢复后可继续。翻译和按需联网查询会通过 Codex 发送相应内容给 OpenAI，沿用该账号的服务与数据设置。论文内容作为待处理数据，不作为程序执行指令。

## 数据与备份

`data/library.sqlite3` 保存文献信息、译文、笔记、偏好和论文对话镜像；`data/library/` 保存 PDF、图片及模型切换交接文件。默认数据位于当前项目的 `data/`，设置中的“存储位置”显示实际路径。使用 `EZREAD_DATA_DIR` 指定其他数据目录。旧环境配置仍由集中兼容层读取；浏览器排序与外观缓存会在确认新值保存成功后迁移到 `ezread-*`。不要删除 `data/`。

“导出备份”生成包含原文、图片、数据库、论文对话镜像、交接资料和可读 JSON 的 ZIP，不包含 Codex 登录配置与官方会话本体。同机可继续原会话；换电脑时旧对话可回看，新提问从交接资料建立新会话。恢复时先关闭后台并保留现有 `data/` 副本，再将备份内的 `data/` 恢复到程序目录。

换电脑时，先等待翻译任务完成或暂停，保存或提交正在编辑的草稿，再在设置中导出完整备份；备份 ZIP 包含个人论文和对话，应私下保存与传输。新电脑安装依赖并登录官方 Codex 后，关闭 EzRead，备份新电脑原有的 `data/`，再把 ZIP 中的 `data/` 解压到应用目录。启动后核对 `/api/health` 的 `app_root`、`data_dir`，并检查论文数量、原件、译文与对话。浏览器中的未提交草稿、侧栏状态等本地存储不在导出包中；官方 Codex 旧会话本体也不会迁移，新提问会依据本地历史与交接资料建立会话。

公开 GitHub 仓库只应包含程序、界面资源和通用文档。`.gitignore` 排除 `data/`、`work/`、`output/`、`AGENTS.local.md` 与常见备份/密钥文件；公开的 `AGENTS.md` 提供架构和协作规则。发布前仍需检查拟提交文件及 Git 历史，确认没有论文原件、译文、对话、截图、账号资料或本机路径。完整备份绝不可随源码上传。

移除文献为软删除，可从回收站恢复；重新导入相同 PDF 也可恢复原有译文与笔记。

## 当前边界

- 主要支持出版社文字型 PDF；扫描件可浏览，当前没有 OCR 全文翻译。
- 原文以页面图片渲染，中文按段落重排，公式保留原图；PDF 字体不能单独替换。
- 双栏、复杂表格与图中文字抽取可能不完整，需结合原文核对。图内文字不直接替换为中文像素。
- 团队简介提供来源，但研究归属仍需核对，通讯作者不一定代表唯一团队。
- DOI 元数据尝试从 Crossref 补全；网络不可用时继续使用 PDF 抽取结果。

## 图标与实现

EzRead 使用用户选定的墨绿展开书本图标：暖白书页、细金色书签与墨绿圆角底。源图为 `assets/branding/ezread-book.png`，应用图标为 `static/ezread-icon.png`，Windows 多尺寸图标为 `static/ezread.ico`；来源及提示词记录见 `ICON.md`。

程序使用 Python 标准库 HTTP、SQLite、pdfplumber/pypdfium2/Pillow 和原生 HTML/CSS/JavaScript；不依赖前端 CDN、npm 构建或额外数据库服务。

## 开发验证

按功能拆分的后端位于 `ezread/`，前端公共能力与功能位于 `static/core/`、`static/library/`、`static/detail/` 和 `static/tasks/`。`server.py` 负责组装与启动，`static/app.js` 负责事件和启动。详见 [架构说明](docs/ARCHITECTURE.md)、[协作约定](AGENTS.md) 和 [贡献与个人定制](CONTRIBUTING.md)。

统一离线检查入口为 `python scripts/check.py`，需要 Python 和 Node.js；不进行真实模型推理。GitHub Actions 在 Windows 上执行同一入口。Node 不在 PATH 时设置 `EZREAD_NODE`。也可以分别运行下列原有入口。

在项目根目录运行以下离线回归测试；没有对应 PATH 时使用本机已确认的 Python、Node 可执行文件路径：

```text
python -m unittest discover -s tests -v
node tests/test_reader.js
node tests/test_detail_notes.js
node tests/test_library_cards.js
node tests/test_browser_storage.js
```

测试使用模拟 Codex 响应或浏览器状态，不消耗模型额度。测试服务须指定独立的 `EZREAD_DATA_DIR` 和空闲端口，测试数据放在 `work/` 下。上述命令是测试入口，不表示当次已执行或通过；单元测试不能代替实际页面滚动、布局、保存恢复以及真实迁移检查，具体完成范围以当次验证记录为准。
